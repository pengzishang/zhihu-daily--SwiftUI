# 今日故事开场｜技术方案概览

## 实现结论

采用最小 SwiftUI 接入方案：新增 `TodayStoryOpeningView`，在 `HomeView` 的第一个日期分节之前渲染 `viewModel.topStories.first`，整块复用现有 `ArticleDetailView` 导航。

## 代码改动

新增：

- `DailyReader/Features/Home/TodayStoryOpeningView.swift`
- `DailyReaderTests/TodayStoryOpeningTests.swift`（或合并进现有密度测试）

修改：

- `DailyReader/Features/Home/HomeView.swift`
- `DailyReader/Features/Home/HomeInformationDensity.swift`
- `DailyReaderUITests/HomeFlowUITests.swift`

不修改：

- `TopStory`、接口、缓存结构、`HomeViewModel` 加载逻辑
- `ArticleDetailView`、收藏、已读和 AI 能力

## 核心复用

- 数据：现有 `HomeViewModel.topStories`
- 图片：现有 `RemoteImageView` + Kingfisher 下采样/缓存
- 占位：现有纸面“日”字占位逻辑
- 设计系统：`DS`、`SealChip`、动态色和宋体
- 导航：现有 `TopStory → StorySummary → ArticleDetailView`

## 密度策略

三档都展示同一条开场，只改变高度、圆角和标题行数：沉浸更高，标准均衡，速览更矮。不开三套组件，不改变内容顺序。

## 风险控制

- 顶部故事为空时完全折叠。
- 图片为空或失败时保留标题与点击能力。
- 不做本地去重，避免改变服务端内容语义。
- Dynamic Type 下允许组件增高，不能固定高度截断标题。
- 使用稳定的 `home.todayStoryOpening` 标识编写 UI 测试。

## 验证

覆盖正常数据、空顶部故事、图片失败、三档密度、进入详情、离线缓存、深色模式、VoiceOver、Dynamic Type 与 Reduce Motion。
