# 原生正文与 WebView 一致性设计

## 目标

在 `DailyReader.useNativeBody` 开启时，让 SwiftSoup 解析后的原生正文对齐现有 WebView 的阅读外观和交互；无法安全、等价映射的 HTML 一律回退到 WebView。

## 已确认范围

- 原生段落、标题和引用支持系统文本选择。
- 长按选中文字后的系统菜单提供“AI 搜索”，把选区传入现有 `openAIChat(selectedText:)`。
- 保持 WebView 已有的字号、墨色、链接、首字朱砂、作者栏、图片预览、讨论按钮、引用、代码块、题注和链接卡片语义。
- 有列表、表格或未支持的嵌入式/样式结构时，整个正文回退 WebView，不渲染降级的半成品。

## 实现边界

1. 为原生正文建立可选择的 UIKit 文本承载视图；它只负责选择与菜单事件，文本排版继续使用现有 `AttributedString` 结果。
2. 原生渲染器在后台解析时同时给出“可原生渲染”判定；解析器遇到不支持的结构返回回退信号。
3. 原生块视图继续复用设计系统 token，避免复制 WebView 的 CSS 常量。
4. 使用同一 fixture 分别启用 WebView 与原生开关，验证可见排版、图片、链接、选区 AI 入口和回退场景。

## 非目标

- 不在原生路径执行文章脚本或远端 CSS。
- 不新增后端或第三方 UI 依赖。
- 不改变文章加载、收藏、已读、分享和 AI 会话的数据流。
