# 文章分类 + 阅读兴趣指数 — 产品需求文档（PRD）

> 本文档为「简单 PRD」，覆盖产品目标、用户故事、需求池（P0/P1/P2）、UI 设计稿要点、依赖与风险、验收标准与待确认边界。设计已评审锁定，所有需求均基于已敲定的 5 支决策，**不再质疑**。语言：中文，不写实现代码。

## 0. 项目信息

- **Language**：中文
- **Programming Language**：SwiftUI / iOS（Swift），基于现有知乎日报-SwiftUI 工程（基于 `version/2.1`，分支 `feature/category-interest`）
- **Project Name**：`article_category_interest`
- **原始需求复述**：在 App 内对文章做 AI 自动分类，并基于阅读行为（滑动百分比、前台停留时长、阅读次数、收藏/不感兴趣）计算每篇文章与每个类目的「阅读兴趣指数」，在「我的」页展示兴趣画像，并在文章列表行展示 AI 类目标签。全程本地、隐私优先。

### 已锁定设计决策（直接作为需求输入）

1. **分类体系**：固定类目。由 AI 对真实文章样本归纳 8–12 个不重叠大类后**冻结**；必有「其他」兜底；冻结前弹「你的阅读类目」页让用户删/并/改名。背景：知乎日报接口无每篇分类字段，`/api/4/themes` 现返回空，分类靠 AI 归纳而非拍脑袋。
2. **AI 分类实现**：进文章（详情加载/刷新）时后台异步调已配置的远程 AI（OpenAI 兼容 Endpoint+API Key，见 `Features/AI`）分类并本地缓存；离线/无 Key 走本地关键词兜底或归「其他」；AI 返回不在集合内或低置信度一律归「其他」。
3. **兴趣信号采集**：复用现有 `ArticleDetailView` 的 `ArticleScrollObserver`（已实时算出 `readingProgress` 滑动百分比 0–1）与 `ReadQualificationTimer`（已用 ContinuousClock+scenePhase 统计前台活跃停留时长）。每篇文章存一条累计汇总：累计停留秒数、最大滑动%、阅读次数、最近阅读时间。收藏=强正信号、不感兴趣(hide)=强负信号。纯本地，绝不联网上报。
4. **兴趣指数算法**：单篇 `score = clamp(0.4×滑动% + 0.4×停留归一 + 0.2×阅读次数)`，收藏额外强正项、不感兴趣≈0（停留用封顶法，单篇≥180s 算满格）。类目指数 = 成员文章得分均值；成员<3 篇标「样本不足」。轻度时间衰减：按最近阅读时间做半衰期≈30 天的指数衰减。
5. **展示**：「我的」页（`MeView`「我的书房」）阅读档案卡下方新增「兴趣画像」卡，横向条形榜按指数降序列各类目（含百分比，<3 篇标样本不足，「其他」置底弱化）；并在首页/收藏列表的每条文章行（`StoryRowView`）加一个 AI 类目标签。

## 1. 产品目标

- **G1**：让用户无需手动打标，自动获得一份清晰的「我常读什么」个人阅读画像。
- **G2**：用极低开发成本（复用现有阅读信号采集链路）为每篇文章贴上可信类目，提升内容可发现性。
- **G3**：全程本地、隐私优先——分类与兴趣数据绝不联网上报，离线可用、无 Key 可用。

## 2. 用户故事

- 作为普通读者，我希望打开文章后 App 在后台自动识别它属于哪一类，这样我不必自己归类。
- 作为重度收藏用户，我希望在「我的」页看到自己的兴趣分布（哪些类目读得多），这样能反思阅读偏好。
- 作为列表浏览者，我希望在首页/收藏列表的每条文章行看到 AI 类目标签，这样能快速判断是否点开。
- 作为注重隐私的用户，我希望我的阅读兴趣数据只存在本机，这样我不用担心被上传。
- 作为老用户，我希望在类目体系冻结前能删/并/重命名类目，这样分类更贴合我的口味。

## 3. 需求池

### P0（必须做）

**P0-1 分类体系**（决策 1）
- 通过 AI 对真实文章样本归纳出 **8–12 个不重叠大类**，冻结为固定集合；必须包含「其他」兜底类。
- 冻结前弹「你的阅读类目」页，允许用户**删除 / 合并 / 重命名**类目。
- 类目集合持久化到本地（建议与 AI 配置同层级的本地存储，见 §5）。
- 背景约束：知乎日报 `/api/4/themes` 现返回空，接口无每篇分类字段，**类目必须由 AI 归纳，不可拍脑袋硬编码**。

**P0-2 AI 分类实现**（决策 2）
- 进文章（详情加载/刷新）时，后台**异步**调用已配置的远程 AI（OpenAI 兼容 Endpoint+API Key，复用 `Features/AI`）对文章分类。
- 复用现有 `AIArticleContextBuilder` 构造上下文（标题+正文，≤24000 字），新增一个分类专用 prompt，要求返回集合内单一类目名（或「其他」）。
- 结果**本地缓存**：每篇文章存 `{ 类目, 置信度, 来源(remote/local), 时间戳 }`。
- 离线 / 无 Key / 调用失败：走本地关键词兜底或归「其他」。
- AI 返回不在集合内 或 低置信度：一律归「其他」。
- 现有网络模型（`ArticleDetail.swift` / `StorySummary`）无分类字段；分类记录应落在**本地缓存层**，不改动网络 Codable 结构。

**P0-3 兴趣信号采集**（决策 3）
- 复用 `ArticleDetailView` 已有的 `readingProgress`（滑动 0–1，由 `ArticleScrollObserver` 实时计算）与 `ReadQualificationTimer`（ContinuousClock + scenePhase 前台活跃停留）。
- 每篇文章维护一条**累计汇总记录**：累计停留秒数、最大滑动%、阅读次数、最近阅读时间、（来自收藏/不感兴趣的）强信号标记。
- 收藏（`homeViewModel.toggleFavorite`）⇒ 强正信号；不感兴趣/隐藏（`homeViewModel.hideStory`）⇒ 强负信号。
- **纯本地，绝不联网上报**。

**P0-4 兴趣指数算法**（决策 4）
- 单篇 `score = clamp(0.4×滑动% + 0.4×停留归一 + 0.2×阅读次数)`，其中停留用**封顶法**：单篇累计停留 ≥180s 算满格（归一=1）。
- 收藏额外加强正项；「不感兴趣」≈0。
- 类目指数 = 成员文章得分均值；成员 **<3 篇** 标注「样本不足」。
- 轻度时间衰减：按最近阅读时间做半衰期≈30 天的指数衰减（`decay = 0.5^(Δdays/30)`）。

**P0-5 展示 — 兴趣画像卡**（决策 5）
- 在 `MeView`「我的书房」阅读档案卡（收藏/已读）**下方**新增「兴趣画像」卡。
- 横向条形榜，按类目指数降序排列，展示百分比；「其他」**置底并弱化**；成员<3 篇标「样本不足」。

**P0-6 展示 — 类目标签**（决策 5）
- 在首页/收藏列表的每条文章行（`StoryRowView`）增加 AI 类目标签。

### P1（建议）

- **P1-1** 「你的阅读类目」管理页支持拖拽排序（影响画像榜顺序）。
- **P1-2** 兴趣画像卡支持点击某类目 ⇒ 跳转该类目下的已读/收藏筛选列表。
- **P1-3** 分类缓存支持失效/重算入口（如更换 AI Key 后「重新分类全部文章」）。
- **P1-4** 首页/收藏列表可按类目筛选。

### P2（可选）

- **P2-1** 兴趣画像随时间变化的迷你趋势（如近 30 天 Top 类目变化）。
- **P2-2** 类目冷启动引导：首次使用弹「我们正在学习你的阅读偏好」空态。
- **P2-3** 兴趣画像导出/分享（纯本地生成图片）。
- **P2-4** iPad 多列布局下画像卡与标签的适配。

## 4. UI 设计稿要点

### 4.1 兴趣画像卡（MeView 新增）

- **位置**：阅读档案卡（收藏 N 篇 / 已读 N 篇）正下方；同款圆角纸面卡片（`RoundedRectangle(cornerRadius: 12, style: .continuous)`，`DS.paperElevated` 底 + `DS.hairline` 描边）。
- **标题行**：「兴趣画像」+ 右侧小字「基于你的本地阅读行为」（弱化，`DS.inkSecondary`）。
- **内容**：横向条形榜（每行一个类目）。
  - 左：类目名（`DS.songBold`）；「其他」用更淡色并强制置底。
  - 中：水平进度条（百分比映射长度），`DS.indigo` 填充。
  - 右：百分比整数 +「样本不足」标签（成员<3 篇时，用 `DS.inkSecondary` 小字）。
  - 排序：指数降序，「其他」强制置底。
- **空态**：无任何分类数据时显示「阅读一段时间后，这里会显示你的兴趣分布」。

### 4.2 类目标签（StoryRowView 新增）

- **位置**：
  - `standardLayout`（medium）：标题上方或 hint 同行右侧的胶囊。
  - `compactLayout`（high）：省略标签，或缩为小圆点，避免破坏 44pt 行高。
  - `immersiveLayout`（low）：置于标题与 hint 之间。
- **样式**：小号圆角胶囊（`Capsule`，`DS.paperElevated` 底 + `DS.hairline`/`DS.indigo` 描边），文字 `DS.inkSecondary`/`DS.indigo`，字号约 11。
- **文案**：类目名；若为「其他」则弱化显示（建议弱化而非隐藏，保持一致性）。
- **可访问性**：胶囊并入整行 `accessibilityLabel`，附「类目：XXX」。
- **显示时机**：仅在已有本地分类缓存时显示；无缓存/离线未分类时**不占位**（避免闪烁）。

## 5. 依赖与风险

- **离线 / 无 API Key**（决策 2）：分类走本地关键词兜底或归「其他」。风险：本地兜底准确度低，需准备一份默认「关键词→类目」映射表；离线时画像可能偏向「其他」。缓解：P1-3 提供重算入口。
- **分类漂移**（决策 2）：AI 返回不在集合内或低置信度一律归「其他」。风险：类目体系冻结后新文章类型增多，「其他」占比攀升，画像失真。缓解：冻结后保留 P1 的「重新归纳/扩充类目」迭代通道（本期不在 P0）。
- **存储依赖**：需在本地新增两类持久化（分类缓存、兴趣汇总）。现有 `HomeViewModel` 用 `UserDefaults` 存收藏/隐藏/已读 + `Keychain` 初始备份；建议分类与兴趣汇总**复用同一本地存储层**（`Storage/`，`UserDefaults` 或 `CacheStore`），并纳入 Keychain 备份迁移模式，避免重装丢数据。
- **性能风险**：每次进文章异步分类 + 汇总写入。缓解：分类请求**去重**（同一文章缓存命中跳过）、汇总写入做**节流/合并**（退出详情或定时落盘）。
- **隐私风险**：必须确保兴趣汇总与分类缓存**没有任何网络上报路径**（现有 AI 调用仅发往用户配置的 Endpoint，不上报阅读行为）。

## 6. 验收标准（供 QA）

- **AC1（分类体系）**：首次跑完归纳后，类目数 ∈ [8,12] 且互不重叠，且包含「其他」；冻结前「你的阅读类目」页可删/并/改名，改名后展示与缓存同步。
- **AC2（AI 分类）**：进入一篇未分类文章，详情加载/刷新后在后台完成分类，列表行出现类目标签；分类结果写入本地缓存且重启 App 后仍保留。
- **AC3（离线/无 Key）**：断网或清空 API Key 时，文章仍可打开，类目走兜底或归「其他」，无崩溃、无上报。
- **AC4（越界处理）**：AI 返回集合外类目或置信度低于阈值时，该类目=「其他」，不污染固定集合。
- **AC5（信号采集）**：在文章内滑动至 100% 并停留，累计停留秒数、最大滑动%、阅读次数正确累加；收藏后强正信号生效；点「不感兴趣」后该篇 `score≈0`。
- **AC6（算法）**：单篇 `score` 落在 [0,1]；停留≥180s 归一为 1；类目指数=成员均值；成员<3 标「样本不足」。
- **AC7（时间衰减）**：模拟最近阅读时间距今 30 天时，该类目指数约为原始的一半。
- **AC8（画像卡）**：`MeView` 在档案卡下方出现兴趣画像卡，条形按指数降序，「其他」置底弱化，<3 篇标样本不足。
- **AC9（标签）**：首页与收藏列表的 `StoryRow` 显示类目标签；compact 布局不破坏行高；无缓存时不占位。
- **AC10（隐私）**：抓包验证：分类与兴趣数据无任何外部网络请求（仅用户配置的 AI Endpoint 用于分类本身）。

## 7. 待确认问题（实现边界）

**无，设计已锁定。** 以下为实现时必须明确的边界：

1. **类目归纳样本量（已确认）**：归纳阶段从「已读/收藏」取真实文章，走 AI 归纳的**下限为 30 篇**（不足则直接用内置 10 大默认类目进入冻结页，避免新用户冷启动卡死），**上限截 500 条**。置信度阈值 0.5、停留封顶 180s、衰减半衰期 30 天、收藏加成 0.25、阅读次数满额 5 次 均作为 `InterestIndexEngine` 的 `static let` 常量，便于后续调参。
2. **类目标签在 StoryRow 的具体位置与各 density 取舍**：medium 标在标题上方胶囊；high 省略或缩为圆点；low 置于标题与 hint 间（需与 §4.2 对齐实现）。
3. **本地关键词兜底的默认映射表**：内置一份静态「关键词→类目」，还是首版直接全部归「其他」。
4. **置信度阈值具体数值**：建议 <0.5 或模型不返回枚举类目即归「其他」（需与 AI prompt 约束一致）。
5. **兴趣汇总落盘时机**：退出详情即写 / 每 N 秒 / 应用进入后台时合并写——影响性能与数据完整性边界。
6. **分类缓存与兴趣汇总的存储落点**：`UserDefaults` 还是 `CacheStore`/专用 Store，以及是否纳入 Keychain 备份迁移（与现有收藏/已读一致）。
7. **「你的阅读类目」管理页入口**：首次归纳完成后的弹窗 / 设置页 / 画像卡右上角编辑按钮。
