# 「今日故事开场」增量产品需求文档

## 0. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品 | 日报阅读器（知乎日报 SwiftUI） |
| 功能名称 | 今日故事开场 |
| 文档类型 | 增量 PRD / 范围确认稿 |
| 适用平台 | iOS 17+ |
| 影响范围 | 日报首页顶部故事区域 |
| 当前阶段 | 需求定义，不修改源码 |
| 数据来源 | 现有 `top_stories` 数据 |
| 上游规范 | `docs/design/design-system.md` |

**一句话定义：**在日报首页顶部，用现有第一条顶部故事建立一个有编辑感的内容开场；用户点击后仍进入现有文章详情，不新增内容、操作或阅读链路。

> 本功能是首页已有内容的呈现优化，不是新的“故事模式”。HTML 原型只用于探索视觉气氛，其中出现的额外交互不自动成为产品需求。

---

## 1. 背景与问题

知乎日报接口已经返回 `top_stories`，项目中也已有 `TopStory` 数据模型、缓存能力和旧版 `TopStoriesView`，但当前 `HomeView` 的已加载状态只渲染日报分节列表，没有展示顶部故事。

这带来两个问题：

1. 首页打开后直接进入结构一致的文章列表，缺少当天最重要内容的视觉入口。
2. 已经获取和缓存的顶部故事没有在当前首页发挥作用。

本需求不是给首页继续叠加功能，而是从现有内容中选出一个明确的开场重点，让“打开日报”更像开始阅读当天一期刊物。

---

## 2. 产品目标

### 2.1 用户目标

- 用户打开日报首页后，能先看到当天一条重点故事。
- 用户可以直接点击开场内容，进入现有文章详情阅读。
- 不需要学习新的操作方式，也不需要先关闭弹层或完成额外选择。

### 2.2 产品目标

- 恢复现有 `top_stories` 内容在首页的价值。
- 在不改变信息架构的前提下，增强首页第一屏的编辑感和每日阅读仪式感。
- 保持需求足够小，避免因视觉概念引入新的数据、状态和维护成本。

### 2.3 成功定义

首版以可验证的体验结果为准，不虚构行为目标值：

1. 有有效顶部故事时，首页第一屏能稳定展示一条开场内容。
2. 点击开场内容可正确进入对应的现有文章详情。
3. 无顶部故事、图片加载失败、离线缓存等情况下，日报列表仍可正常使用。
4. 页面不出现来自 HTML 概念稿但未被需求定义的额外功能。

---

## 3. 范围

### 3.1 首版必须做（P0）

1. **展示位置**
   - 首页进入 `.loaded` 状态后，在第一条日期分节之前展示“今日故事开场”。
   - 开场属于首页滚动内容，不做全屏弹层、启动页或独立页面。
   - 用户向下滚动后自然进入现有日报列表。

2. **内容选择**
   - 使用现有 `topStories` 中第一条有效数据。
   - 首版固定展示一条，不提供切换、轮播或故事进度。
   - 不改变服务端排序，不在本地重新推荐。

3. **展示字段**
   - 仅使用现有模型可靠提供的字段：`title`、`image`。
   - 可使用固定界面标签“今日故事”，用于说明区域身份。
   - 不展示作者、摘要、栏目、发布时间等当前 `TopStory` 模型未提供的信息。
   - 不从标题或图片内容中推断、生成补充文案。

4. **进入阅读**
   - 整个开场区域可点击。
   - 点击后复用现有 `ArticleDetailView` 和日报来源链路。
   - 已读记录、收藏、正文阅读等行为沿用文章详情现有能力，不在开场区域重新实现。

5. **视觉方向**
   - 使用顶部故事图片作为主要视觉；保证标题在图片上清晰可读。
   - 整体遵循“今日刊”设计系统，不引入一套独立品牌皮肤。
   - 允许强化首屏气氛，但不使用会阻断阅读的片头动画。
   - 不自动播放声音、视频或连续动画。

6. **状态处理**
   - `topStories` 为空时，整个开场区域不渲染，不保留空白，首页直接显示现有日报列表。
   - 图片为空或加载失败时，使用项目现有纸面占位逻辑，标题和点击能力仍保留。
   - 离线且缓存中存在顶部故事时，按现有缓存数据展示。
   - 下拉刷新后，开场内容随现有首页数据一起更新，不新增独立刷新入口。

7. **可访问性与适配**
   - 整个开场区域提供明确的辅助功能标签和“打开文章”的提示。
   - 标题支持 Dynamic Type；字号放大时优先保证完整可读，不强行维持固定首屏比例。
   - 支持 VoiceOver、深色模式和“减弱动态效果”。
   - iPhone 与现有 iPad/宽屏布局均不得横向溢出。

### 3.2 可以后续评估（不进入首版）

- 是否从“一条开场”扩展为多条顶部故事浏览。
- 是否根据数据决定用户可关闭或弱化开场。
- 是否增加独立的曝光与进入阅读统计。

这些事项必须经过单独需求确认，不能在实现首版时顺手加入。

---

## 4. 明确不做（Non-goals）

首版不包含以下能力：

- 不做多故事轮播、分页圆点、进度条或左右切换。
- 不做自动轮播、定时切换和视频片头。
- 不做声音开关、背景音乐或环境音。
- 不新增“有启发”“点赞”“评论”“分享”“收藏”快捷按钮。
- 不在开场区域显示阅读进度。
- 不新增“开始阅读”流程或二次确认；点击内容直接进入现有详情。
- 不生成作者、摘要、栏目、日期或任何接口没有返回的内容。
- 不修改推荐算法、接口、缓存结构或 `TopStory` 数据模型。
- 不修改文章详情页及其现有收藏、已读、AI 等功能。
- 不调整底部导航、首页信息密度设置、日期分节和历史分页规则。
- 不把开场做成首次启动引导、广告位或每天必须关闭的遮罩。

---

## 5. 用户故事

1. **作为日报读者，我希望打开首页时先看到当天一条重点故事，以便快速理解今天最值得关注的内容。**
2. **作为想继续阅读的用户，我希望点击开场内容直接进入文章详情，以便不经过新的中间步骤。**
3. **作为只想浏览普通列表的用户，我希望向下滚动即可进入日报列表，以便原有阅读方式不被打断。**
4. **作为使用辅助功能的用户，我希望标题和点击区域可被正确识别，以便独立完成阅读。**

---

## 6. 页面与交互规则

### 6.1 页面顺序

```text
首页导航栏
今日故事开场（仅在有有效 top story 时出现）
第一条日期刊头
当日文章列表
后续日期分节
历史分页
```

### 6.2 点击规则

- 点击开场任意位置，进入该顶部故事对应的 `ArticleDetailView`。
- 不在卡片内部增加多个点击目标。
- 返回首页后，保留系统导航的既有行为；不额外记录或恢复开场动画状态。

### 6.3 滚动规则

- 开场与日报列表共用首页现有纵向滚动。
- 不锁定滚动，不要求用户点击按钮才能查看下方列表。
- 下拉刷新继续由首页统一处理。

### 6.4 动效规则

- 首版只允许轻量、非阻断的内容出现过渡。
- 开启“减弱动态效果”时取消非必要过渡。
- 不延迟用户点击，不以动画播放完成作为进入阅读的前置条件。

---

## 7. 数据映射

| 界面内容 | 数据来源 | 规则 |
| --- | --- | --- |
| 今日故事标题 | `TopStory.title` | 必须存在；沿用模型当前有效性判断 |
| 主图 | `TopStory.image` | 可为空；为空或失败时使用现有占位逻辑 |
| 跳转目标 | `TopStory.id` / `TopStory.url` | 复用当前 `TopStory.summary` 与文章详情链路 |
| 区域标签 | 固定界面文案“今日故事” | 不代表服务端栏目 |
| 已读状态 | 现有 `readStoryIDs` | 如视觉需要区分，沿用现有已读语义，不新增状态 |

**禁止映射：**HTML 原型中的作者、阅读时长、摘要、故事编号和环境声音均无可靠现有数据来源，首版不得展示。

## 8. 验收标准

### 8.1 正常数据

- [ ] `topStories` 非空时，第一条有效顶部故事展示在首个日期分节之前。
- [ ] 页面只展示一条开场内容，没有轮播控件和分页进度。
- [ ] 标题和图片内容与接口数据一致，没有自动生成的补充信息。
- [ ] 点击开场区域能进入对应文章详情。
- [ ] 向下滚动可直接进入现有日报列表。

### 8.2 异常与边界

- [ ] `topStories` 为空时不展示开场，也不留下空白区域。
- [ ] 图片为空、加载失败或网络较慢时，标题仍可读且区域仍可点击。
- [ ] 离线缓存场景不影响首页现有离线提示与日报列表。
- [ ] 下拉刷新成功后，开场与首页数据保持一致。
- [ ] 超长标题、大字号、深色模式和宽屏下无截断关键语义、遮挡或横向溢出。

### 8.3 范围检查

- [ ] 没有声音、视频、自动轮播、故事进度或多故事切换。
- [ ] 没有在开场区域新增启发、点赞、收藏、分享等操作。
- [ ] 没有新增接口字段、推荐逻辑或文章详情功能。
- [ ] 没有修改首页原有日期分节、历史分页、下拉刷新和信息密度行为。

---

## 9. 实现前确认

本文件只确认产品范围，不直接授权修改源码。进入实现前只需再确认两件事：

1. 开场在三档首页信息密度下是否都展示，还是仅在“沉浸”档展示；默认建议三档都展示，但在“速览”档降低高度，避免改变内容入口的一致性。
2. 最终视觉稿需要基于本 PRD 删除 HTML 概念稿中的额外交互，只保留单条开场、标题、图片和直接进入详情。
